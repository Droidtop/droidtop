# Legacy IME per-key accessibility: bounded static follow-up

Reviewed source at Droidtop 5ee197cce5 (Slab branch); no runtime, TalkBack, geometry or device claims. No candidate files changed.

## Current gap and existing seams

- `input-keyboard/src/main/java/org/pocketworkstation/pckeyboard/LatinKeyboardBaseView.java:82` is a canvas View. Its draw entry is :916 and touch entry :1836. The module source has no legacy onHoverEvent, AccessibilityNodeProvider, ExploreByTouchHelper or per-key accessibility initialization. Slab's new helper does not cover this view.
- Keys are concrete `Keyboard.Key` objects with x/y/width/height (:276-289), label/shiftLabel/capsLabel (:267-269), codes (:264), text (:304), popupCharacters (:306), popupResId (:327). `Keyboard.applyForm` :920 transforms these actual coordinates before consumers read them, covering split/one-handed width and floating height; do not recompute geometry from XML or assume a contiguous grid.
- Drawing translates by key.x/y plus View padding (`LatinKeyboardBaseView:1202`), and obtains the actual case label at :1189. Semantic bounds should use that same rectangle plus padding, clipped to the visible host; hover hit testing should use exact visible rectangles rather than proximity detection across split gaps. Press animation scales visual plates temporarily; whether fixed hit geometry is acceptable needs rig verification.
- `setKeyboard` :700 cancels timers, replaces mKeys via KeyDetector at :712, resets each PointerTracker at :716 and requests layout. This is the primary generation boundary. `onSizeChanged` :906, shift/meta indicator mutations around :748-790, popup show/close (:1653, :2050), and `closing` :2009 also require semantic refresh/cleanup.
- Existing delivery authority is `PointerTracker.detectAndSendKey` :584-630. It handles output text, nearby-code arrays, multi-tap replacement and release callbacks. Calling only listener.onKey is not equivalent. Listener.onPress may itself change layouts (`PointerTracker:308-310`); LatinIME.onPress :3667 handles Shift/mode/Ctrl/Alt/Meta/Fn state and native modifier down. LatinIME.onRelease :3712 commits/resets modes and releases native modifiers.
- Mini-keyboards use another LatinKeyboardBaseView and forward all press/key/text/release callbacks (:1572-1603). Extension rows likewise instantiate LatinKeyboardView and forward listener callbacks (`LatinKeyboardView:452-515`). A helper in the base class can cover their keys, but popup windows need their own visible ownership/focus lifecycle. Base keys must not stay actionable behind a visible modal mini-keyboard.

## Concrete safe follow-up scope

1. Extract one explicit, package-private semantic activation seam in PointerTracker using the same key-output core as touch, preserving balanced press/release and text/dead-key/multi-tap behavior. Pass an exact key object/generation, resolve the permitted replacement after onPress as current touch code does, and abort stale nodes. Do not synthesize timed MotionEvents or introduce another IME output implementation. No accessibility hover may type or start repeat/glide/haptics.
2. Add an ExploreByTouchHelper in LatinKeyboardBaseView, with monotonically generated IDs or per-generation ID map keyed by Key identity/index. Never use code as ID: left/right Shift and repeated codes are legal. On keyboard replacement, clear vanished accessibility focus before invalidation; never let an old ID activate a new layout's key.
3. Use getCaseLabel for visible text plus explicit localized names for icon/control/dead keys and enter actions. Checked state must come from current Keyboard/LatinIME modifier state, not merely key.pressed. Announce state changes without stealing the editor's actual input focus; keep the host and virtual nodes out of real keyboard focus as Slab does.
4. Advertise click only for an implemented ordinary activation. Add named long-click for popup only when that path can open a semantically traversable popup, with deterministic return focus on close. Treat mini-keyboard and extension window lifecycle explicitly; do not claim popup parity from base-key nodes alone.
5. CI-only attached-view provider tests: all live layouts and forms have unique IDs/in-bounds geometry; split gap hits no key; Shift/mode swap during onPress cannot deliver stale character; text/dead keys and modifier down/up preserve editor focus; duplicate Shift keys work independently; old IDs fail after language/size/layout change; mini-keyboard focus closes and returns correctly. Test extension rows as a separate host. Existing touch tests must retain repeat, glide and multi-touch behavior.

## Deliberately separate acceptance

Source/CI can establish model mapping and callback behavior. Actual TalkBack exploration, spoken labels across locales, popup-window traversal, narrow/split/floating geometry and touch coexistence still need a future rig check. This follow-up is not a claim that all #903 visual/typing requests are implemented.

## Implemented candidate after this audit

The isolated follow-up implements ordinary per-key virtual nodes, exact clipped rectangles/hover hits, identity-qualified IDs, current case/control labels, modifier state, separate visual accessibility focus and editor input-focus retention. A dedicated semantic PointerTracker uses the existing output core and independent multi-tap history, refreshes on layout/listener change and rejects activation during active physical touch. Ordinary layout-changing presses abort with release; known mode/modifier presses retain original intent. Popup opening through a long-click is deliberately not advertised: the existing opener injects a touch-down and needs a separate semantic path. Already visible mini-keyboards suppress underlying nodes/actions; extension and mini-keyboard instances inherit the base adapter. Actual popup traversal is not established by a suppression unit test.

Nine authored attached-view Robolectric tests cover duplicate IDs and split gaps, clipped geometry, char/text output and editor focus, stale nodes/focus, layout changes during ordinary and modifier presses, popup suppression, dead-key/multi-tap output, modifier-state/resize refresh, and physical/semantic input separation. CI is the only build/test execution environment; no TalkBack or device claims follow from this source review.
